# Cache scaling at 71K tokens, and the first citation baseline

**Date:** 2026-07-30
**Track:** context strategy (CS-A follow-through; answers the open CS-B question)
**Spec:** `docs/superpowers/specs/2026-07-29-hybrid-context-strategy-design.md`
**Prior spike:** `docs/superpowers/spikes/2026-07-29-gemini-context-caching-findings.md`

Two measurements, taken after CS-A merged (PR #123). CS-A shipped the
instruments; this is the first set of readings.

---

## 1. Implicit prefix caching does not degrade with prefix size

**Question.** The prior spike measured a 56.6% implicit cache hit on a tiny
corpus, and a smoke run showed 57.6% on hillpath (~4K tokens total). CS-B's
whole shape depended on whether that rate survives a realistic prefix — if it
collapsed, column batching would be necessary despite the surgery it requires.

**Method.** 12 Financial DD columns, one row, over the Activision 2023 Q2 10-Q
*only* (75pp, ~71K tokens per prompt), driven through the real `execute_run`
path so calls are attributed `surface="tabular_cell"`. Run
`24a6166fc7fd44e29b532611674dc361`. Concurrency is the product default
(`max_concurrent_llm_calls = 3`).

**Result.**

| call | prompt | cached | hit |
|---|---|---|---|
| 1–4 | ~71,240 | 0 | 0% |
| 5–12 | ~71,240 | 65,503 | **92%** |

Aggregate 61.3%; steady state **92.0%**. `llm_metrics.summarize` returned
figures identical to the raw table — the first validation of the CS-A
instrumentation at real scale.

**Reading.** The rate does not degrade with prefix size; it nearly doubles.
The ~5,740 tokens that stay uncached per call are the per-column question,
system prompt and output directive — exactly the portion that *cannot* be
shared between cells. The four cold calls are the concurrency window racing
ahead of the first cache write.

**Consequence for CS-B: do not build column batching.** Batching (spec 1c)
breaks four load-bearing mechanisms in `workflow_run_executor` — the atomic
claim, per-cell SSE, per-cell retry, and semaphore dispatch — in order to stop
sending a document once per column. Those tokens are already 92% cached and
cached input bills at ~10× less. The surgery no longer has an economic case.

The one remaining cost lever with real headroom is the **cold window**: 4 of
12 calls paid full price because they started before any cache existed. That
is a dispatch-ordering question (warm one cell, then fan out), not an
architecture change.

### Side effect: CS-A5 is effectively resolved

CS-A5 asked whether `cached_tokens` accumulates across stream chunks or is
last-non-zero-wins, and warned that CS-B must not trust summed values until
answered.

All 8 warm calls reported **exactly 65,503** while completion length varied
from 53 to 449 tokens. Per-chunk accumulation would make longer outputs sum
higher. They do not. The value is a single report.

Not formally conclusive — 449 tokens is still not a long stream — but the
accumulation hypothesis is falsified for this path, and the sums in
`llm_metrics.summarize` can be trusted.

## 2. Citation baseline: 44/44, and that is the problem

**Method.** `evals/data/brightwater_golden_set.json` — 44 questions over 9
documents / 95 pages of the Brightwater/Glenmoor corpus, run through
`run_extraction` directly.

```
hit_rate         1.000
mean_precision   0.955
no_citation_rate 0.000
questions        44
```

**Every question cited the correct page.** Four cited one extra page:

| question | cited | the extra page |
|---|---|---|
| `ddq-team-succession` | 2, 3 | p3 lists Roache on the IC — arguably responsive |
| `adv-affiliated-broker-dealer` | 6, 9 | p9 covers related-party compensation |
| `fs-level3` | 2, 6 | p2 is the balance sheet carrying those assets |
| `ddq-track-record` | 4, 8 | p8 is valuation — the weakest of the four |

Three of four are defensible supporting citations rather than errors, so true
precision is higher than 0.955.

**The finding is that the baseline is saturated.** A metric pinned at 1.000 has
no headroom: it can detect a regression but can never show an improvement. For
the spec's stated use — run the golden set under `full_text` and `auto`, and
require that the allocator not degrade accuracy — a regression detector is
exactly what is needed, and this serves. As evidence that any future retrieval
change *helps*, it is structurally incapable.

**Why it saturated.** As predicted when the corpus was adopted, these documents
are generated by `scripts/generate_brightwater_docs.py`. The LPA is literally
one section per page; formatting is uniform; there is no OCR noise, no scanned
tables and no drafting variance. The number is a ceiling. It should never be
quoted as production citation accuracy.

**If a discriminating baseline is wanted later**, the corpus has to get harder
in ways the generator does not currently produce: facts split across a page
boundary, the same term defined differently in two places within one document,
tables that continue across pages, and near-duplicate pages where only one
carries the operative number. The Activision 10-K (312pp of real filing prose)
is the available corpus that already has those properties, at the cost of being
the wrong domain.

## Open

- **Cold-window mitigation** — 4 of 12 calls uncached is the largest remaining
  cost item; worth a dispatch-ordering experiment before anything more invasive.
- **Embedding spend is invisible.** `vector_store.upsert_chunks` calls
  `embedder.embed_texts` with no `full_context_mode` guard, one API call per
  chunk, and none of it reaches `llm_calls` — that table covers only generation
  through `stream_with_fallback`. Ingesting the 13-document Brightwater pack
  silently made 182 embedding calls. CS-C's lazy/batch embedding would spend
  money the cost route cannot see.
- **`run_eval` has no good database target.** Against a DB that has run
  `init_db` it writes `surface=unknown` rows that pollute cost measurement
  (the README warns of this); against a fresh DB it raises a caught traceback
  per call because `llm_calls` does not exist, and records no tokens. Either
  `_record` should degrade quietly or the runner should create the table.
- **A genuinely long-output call** would close CS-A5 formally rather than
  persuasively.
